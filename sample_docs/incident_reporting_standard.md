# Incident Reporting Standard

## 1. Purpose
This standard defines how security incidents must be reported and handled.

## 2. Scope
Applies to all employees, contractors, and third parties.

## 3. Definition of Security Incident
A security incident includes:
- Unauthorized access to systems or data
- Malware infections
- Phishing attempts
- Data loss or leakage
- Suspicious system behavior

## 4. Reporting Requirements

### 4.1 Immediate Reporting
- All suspected incidents must be reported within **1 hour** of detection

### 4.2 Reporting Channels
Incidents must be reported via:
- ServiceNow security incident form
- Security hotline
- Dedicated email (security@company.com)

## 5. Information to Include
Reports should include:
- Description of the incident
- Time of occurrence
- Systems affected
- Any actions already taken

## 6. User Responsibilities
Users must:
- Not attempt to investigate beyond their expertise
- Preserve evidence where possible
- Follow instructions from the security team

## 7. Security Team Responsibilities
The security team will:
- Assess severity
- Contain and remediate the incident
- Communicate with stakeholders

## 8. Incident Classification
Incidents will be classified as:
- Low
- Medium
- High
- Critical

## 9. Post-Incident Review
- All major incidents require a post-mortem
- Lessons learned must be documented

## 10. Enforcement
Failure to report incidents may result in disciplinary action.
